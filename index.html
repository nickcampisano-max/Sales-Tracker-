How this runs each week
  1. Open workbook and pick the latest .json from the shared Drive folder. Skip it if the browser already remembers — the badge in section 4 tells you.
  2. Pull the three Sales by day exports from Toast and drop all three at once. Same date range on all three, or days will come in partial.
  3. Check the preview, then write them in. Anything that overwrites an existing number is reported.
  4. Set next week's target in section 6 and Commit & lock it.
  5. Save workbook and Export for Drive, then put both files in the shared folder. The .json is what the tool reads next week; the .xlsx is the one people read.
Nothing is uploaded anywhere — this page has no server. The browser keeps a working copy so a crash or an accidental refresh doesn't lose the day, but the file in Drive is the record. If the two ever disagree, the file wins.

Notes — how this differs from the spreadsheet

PM is imported, not back-solved. The spreadsheet typed TOTAL NET and derived PM = Total − AM − ATP. Here every bucket arrives from its own export and the total is their sum, so there is nothing left to reconcile.

The variance sign is flipped, deliberately. The spreadsheet computes Projection − Actual, so a negative number reads like a shortfall when it actually means a beat. This uses Actual − Projection: green positive is a beat. Same magnitudes, opposite sign.

Committed projections freeze. In the spreadsheet, P8 WK4 was forecast at $50,000 on one sheet and $51,000 on another, so variance moved with the baseline. Here a commit is a snapshot; later edits are logged as revisions and the headline variance always uses the original.

The comparison range is explicit. The old “Difference” cell meant Mon–Thu on one sheet, Mon–Sat on another and the full week on a third — identical-looking cells, three meanings. Here it's a labeled control and both sides always use the same days.

Partial days stay blank rather than zero. Toast omits closed days, and the three exports often cover different ranges. A missing bucket is left empty and the day is marked partial, so an unpulled report can't quietly drag a weekly total down.

Projections are distributed, not forecast. You give it one weekly number; it splits that across days and buckets using the trailing mix from complete weeks and shows you the percentages it used. It does not try to predict the total — on this data a fitted trend would be reading noise, and it would carry the false authority of a computed figure.

Self-contained page, no network requests, no data leaves this browser.
